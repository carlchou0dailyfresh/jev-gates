# JEV 語意工作台

工作台把一份工作拆成「工作與證據 → 語意判斷 → 三值邏輯 → 判斷支線 → 文字草稿」。你可以修改工作內容、證據、每個判斷問題與門檻，再觀察這些改動如何影響結果。

它適合研究可檢查的 AI 工作流程。它沒有執行退款、扣款、部署、寄信或其他外部業務操作，也不能用來證明已實現 AGI。

## 在本機啟動

工作台需要 Node.js 22.12.0 以上版本。在儲存庫根目錄執行：

```sh
npm ci
npm ci --prefix workbench
npm run workbench:dev
```

開啟 <http://127.0.0.1:3088>。服務只綁定本機回送介面，不是已部署的公開網站。若連接埠已被使用，可在啟動前設定 `WORKBENCH_PORT`。

要使用已建置的前端：

```sh
npm run workbench:build
npm run workbench:start
```

建置與啟動是兩個步驟；修改前端後應重新建置。`workbench:start` 不會替你產生新的前端建置檔。

## 先選擇執行模式

| 模式 | 判斷來源 | 適合研究什麼 |
| --- | --- | --- |
| 固定示範（fixture） | 案例預設或使用者調整的固定數值 | 門檻、TRUE／FALSE／UNKNOWN、組合邏輯與支線互動 |
| LocalJev | 本機 `http://127.0.0.1:8080` 的 JEV 相容服務 | 用實際模型重新判斷目前工作與證據 |
| TypeSafe JEV | 伺服器端使用 TypeSafe API | 在已設定金鑰的環境執行 TypeSafe JEV 判斷 |

**固定示範不會理解文字變更。** 改寫工作或證據後，只要固定數值與門檻不變，判斷結果也可能完全相同。這是流程示範，不是模型準確率測試。

LocalJev 是 JEV 相容的本機橋接服務，不能把它的結果標成 TypeSafe JEV 模型結果。應同時查看橋接服務及其實際上游模型；服務可連線也不等於已完成一次推論。

若使用 TypeSafe JEV，請在啟動工作台的伺服器環境設定 `TYPESAFE_API_KEY`。金鑰不能放進案例、證據欄位、前端程式、瀏覽器儲存空間或匯出的研究報告。未設定金鑰時，介面不應宣稱 TypeSafe 已可用。

## 建立一輪可比較的實驗

1. 選擇案例，先閱讀工作目標與標有 `E1`、`E2` 等編號的證據。
2. 修改工作目標、證據內容及判斷問題。每個問題盡量只問一件可由目前資料判斷的事。
3. 調整要啟用的判斷與 FALSE／TRUE 門檻。兩個門檻之間保留 UNKNOWN 區間；不要為了得到想要的支線而宣稱任意門檻已校準。
4. 選擇 AND、OR 或至少 k 項成立的組合方式。至少保留一個啟用的判斷；使用 k-of-n 時，k 不得大於啟用數。
5. 編輯 TRUE、FALSE、UNKNOWN 三條支線的名稱與文字指示。UNKNOWN 應保留補資料或暫緩結論的處理方式。
6. 執行判斷，檢查每個節點的狀態、回傳值、執行來源、耗時及最終支線。
7. 需要自然語言時，再產生一份以該次結果與證據為基礎的文字草稿。

修改設定後，先前結果只對應修改前的快照。重新執行才能取得目前版本的結果；不要把舊支線或舊文字當成新設定的結論。研究比較時，建議每次只改一個因素，例如一份證據、一個問題或一個門檻。

## 四個案例怎麼玩

所有預設案例都是合成資料或虛構情境，沒有讀取真實顧客、真實交易或即時營運資料。

| 案例 | 研究焦點 | 建議調整方式 |
| --- | --- | --- |
| 冷鏈試點，值得擴大嗎？ | 區分觀察到改善與已證明因果 | 修改是否有同期對照、是否同時變更多個因素，觀察因果證據判斷；固定分數只用來展示邏輯 |
| 一則客訴，該交給誰？ | 辨識品質問題、處理意圖及工作指引的語意匹配 | 把訊息改成詢問配送進度或單純留言；以真實模型模式重新判斷分流 |
| 付款異常，要先查哪裡？ | 區分異常現象、逾時線索與已確認根因 | 移除逾時紀錄或加入相反證據，觀察調查建議；不能推論付款成功或自行再次扣款 |
| 雨天的親子行程怎麼改？ | 把多個質性偏好組合成候選方案建議 | 修改餐館入口與移動是否遮雨，比較 AND、OR、k-of-n 的結果 |

付款案例只產生調查交接草稿。親子案例中的場館與餐館是虛構設定，沒有查證真實營業時間、價格、天氣或無障礙設施。

預設案例的固定數值是教學設定，並非人工標註的正確答案；尤其 UNKNOWN 範例是展示流程如何保留不確定性，不代表模型應該輸出相同數值。

## TRUE、FALSE 與 UNKNOWN

每個語意問題取得一個回傳值，再由明確的門檻轉成三種狀態：

- TRUE：達到該判斷的成立門檻。
- FALSE：達到該判斷的不成立門檻。
- UNKNOWN：模型或固定示範的回傳值落在兩個門檻之間，尚未達到成立或不成立的條件。

UNKNOWN 不是 FALSE。工作台遇到模型逾時、服務錯誤或無效回應時，會顯示錯誤而不產生替代結果；這與取得有效回應但落在 UNKNOWN 區間是不同情況。

AND、OR、k-of-n 由程式組合節點狀態，不是再請語言模型猜一次。最後的 TRUE 只代表目前設定下的邏輯結果，不代表現實一定為真；也不能把節點分數乘起來當成整個工作的正確率。

金額計算、日期比較、明確的數值限制，以及帳號是否擁有操作權限，應由確定性的規則或實際授權資料判斷。語意模型適合處理語句的意圖、證據是否支持某項主張等質性問題。

## 橋接大模型產生文字

判斷與寫作是兩個步驟。工作台可把已完成的那次判斷、命中的支線、工作目標及證據交給本機 Ollama，產生繁體中文草稿。

語言模型服務預設位於 `http://127.0.0.1:11434`。需要先在自己的 Ollama 環境備妥可用的本機模型；工作台不會因本機模型無法使用而悄悄改用雲端模型，也不會自動下載大型模型。

固定模板摘要與模型生成文字應分別辨識。看到模板摘要不代表大模型已執行；看到 JEV 判斷完成，也不代表文字生成已成功。

文字草稿仍需人員檢查：

- 引用的 `E1` 等編號必須來自這次執行所保存的證據。
- 有合法的證據編號，不代表每句話都已被該證據支持。
- 不應把推測寫成確認事實，也不應把建議寫成已完成的退款、重啟或其他行動。

## 保存與重播

瀏覽器中的草稿與歷史紀錄用於本機操作，不是多人共用的資料庫或備份。瀏覽器清除網站資料、改用不同瀏覽器或換一個連接埠，都可能使原本的本機紀錄不可見。完成一輪重要比較後，應匯出該次結果留存。

若服務重啟後無法再為舊紀錄生成文字，可使用同一份草稿重新執行判斷。匯出的報告包含工作內容及證據文字，分享前應先確認沒有不適合分享的資料。

也可以從儲存庫根目錄產生可重現的固定研究示範：

```sh
npm run research:demo
npm run verify-report -- .jev-runs/research-demo.json
npm run replay -- .jev-runs/research-demo.json
```

預設報告位於 `.jev-runs/research-demo.json`，包含四個案例及一個另外標示的「UNKNOWN 門檻實驗」。後者刻意調整固定數值，只用來演示未決支線。`verify-report` 與 `replay` 使用本機報告，不需要呼叫 JEV、Ollama 或其他網路服務。

離線驗證用來檢查報告結構、輸入與電路對應關係；重播用來確認保存的判斷回應能依相同規則重建結果。**這些檢查證明紀錄與運算的一致性，不證明輸入資料、模型判斷或語言草稿在現實中為真。**

若要評估真實品質，仍需要獨立標註、保留測試集、不同工作情境、門檻校準及失敗案例分析。介面的測試通過率與固定示範結果，都不能替代真實 JEV 準確率。

## 遇到問題

| 狀況 | 檢查方式 |
| --- | --- |
| 頁面無法開啟 | 確認工作台仍在執行，以及網址的連接埠是否與 `WORKBENCH_PORT` 一致 |
| LocalJev 不可用 | 確認本機 8080 服務及其上游模型已就緒；可先用固定示範檢查介面流程 |
| TypeSafe 未設定 | 在伺服器啟動環境設定 `TYPESAFE_API_KEY`，再重新啟動；不要在頁面貼入金鑰 |
| 無法產生文字 | 確認 Ollama 11434 服務及本機模型可用，並先完成目前設定的一次判斷 |
| 結果沒有隨文字改變 | 檢查是否仍使用固定示範；固定數值不會分析文字 |
| 顯示 UNKNOWN | 檢查節點回傳值與兩個門檻，再評估是否需要修改問題或補充證據 |
| 舊結果與目前設定不一致 | 重新執行；舊結果保存的是當時的輸入快照 |

更多核心語意與限制見 [電路格式](circuits.md)、[評估方法](evaluation.md) 與 [驗證說明](verification.md)。
