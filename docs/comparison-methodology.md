# 與 Google Maps 比較的方法

本文件說明比較設計與證據邊界；方法成立不表示目前已收集足夠實地樣本。Google Maps 是另一個預估來源，不是實際到站時間的標準答案。

## 分清楚比較對象

| 比較項目 | 必須相同的條件 | 結果能說明什麼 |
| --- | --- | --- |
| 汽車行程預估 | 同起終點、出發時刻、交通模式、避開高速/收費等選項 | 當次路線或行程預估差異；尚非準確率 |
| 同一班公車到同一站的預估 | 同路線、方向、站牌、班次或可確認的車輛、近似同一查詢時間 | 候車預估差異；班次不明時不能當配對樣本 |
| 實際抵達誤差 | 抵達前已凍結的預估，以及後來獨立記錄的同一趟實際抵達 | 這份樣本的預估誤差 |
| 趕車建議 | 上述公車條件、步行路線與時間、緩衝時間、使用者需求 | 在已知條件下的可行性建議；不是準時保證 |

不要拿汽車全程時間、公車剩餘候車時間、上車後乘車時間或包含步行轉乘的門到門時間互相比較。兩個數字單位同為分鐘，也可能描述完全不同的事情。

Google 官方指出 Google Maps / Waze 可能因參數及後續路況變化，得到不同於 Routes API 的路線。介面應明確分別標示「Google Maps 使用者觀察」與「Google Routes API」，不能把 API 呼叫當作 Maps App 的實測結果。[官方 FAQ](https://developers.google.com/maps/documentation/navigation/connect/faq)

Google Maps 的大眾運輸資訊也可能是即時預估或時刻表；比較欄位應保留 `live`、`scheduled`、`unknown`。只看到一個到站時刻，不足以判定它是即時預估。[Google Maps 公車與列車說明](https://support.google.com/maps/answer/6142130)

## 先凍結預估，再記錄抵達

1. 建立試次：確認交通模式、起終點或站牌、方向、班次及時區，記錄查詢開始時間。
2. 分別記錄每個來源的「觀察時間」與可取得的「來源更新時間」。兩者不能互相代替；畫面沒有來源時間時保持未知。
3. 以近似同一時刻取得比較值；本版要求兩次觀察相差不超過 120 秒作為配對條件，這是研究設定而非官方準確性標準。超出者保留為非同步樣本。
4. 在實際抵達前凍結兩份預估。後續來源刷新應新增觀察，不能覆寫已凍結值。
5. 抵達後記錄實際時刻及證據方式，例如站牌現場人工按鈕、本人行程記錄或另有授權的實際車輛到站紀錄。人工輸入應標為使用者回報，不宣稱已被系統獨立驗證。
6. 沒有實際抵達時刻時，只顯示「估計差異」。實際時刻早於凍結、班次無法配對或觀察缺時區時，排除準確度計算並說明原因。

若來源給剩餘秒數，凍結時應轉成帶時區的預估抵達時刻。倒數至零表示原預估時間已過，不是車輛已經到站的證據；在沒有新來源更新時，不可一直顯示「即將到站」。

可以計算每筆誤差 `預估抵達 − 實際抵達`、絕對誤差、MAE 與樣本足夠時的第 90 百分位。正負誤差、缺資料比例與未配對數量應一起顯示。百分比誤差不適合很短或為零的剩餘候車時間。少數試次只報樣本結果，不產生「全面優於 Google」或「JEV 真實準確率」結論。

## 有意義的情境

預先選定情境，記錄所有成功與失敗樣本，避免只留下有利結果：

- 市區短程汽車行程：分平峰與尖峰，記錄兩者是否選了不同路線。
- 跨區汽車行程：記錄高速/收費等設定，不能將設定不同造成的差異歸為模型失誤。
- 公車候車：同一路線的去返程分開；另區分短時間即將到站與較遠時間預估。
- 異常或缺資料：來源過期、沒有即時值、班次取消或無法配對時，檢查是否正確顯示未知。
- 接駁需求：先確定步行時間與緩衝，JEV 只解析使用者需求或公告內容，數值計算仍由程式完成。

路段車速、警廣事件與公車預估是不同來源。附近某段車速較慢可以提供情境，但沒有經過道路方向匹配與實地校準前，不應拿它改寫公車 ETA。人工智慧也不能靠文字判斷替代來源時間檢查。

## Google 資料使用邊界

Google Maps 終端條款涵蓋觀看、註記及符合規定的展示，也對複製、批量下載及建立替代地圖資料集設限。「私人比較」本身不是條款所列的全面豁免。本工具宜維持少量、使用者主動提供的當次觀察，清楚註明來源與時間；不自動擷取 App 內部端點、不建立 Google 路線資料庫，也不把觀察內容當成 JEV 的訓練或驗證標籤。這是縮小功能範圍的設計選擇，不是 Google 對個案的授權聲明。[Maps 終端條款](https://www.google.com/intl/en_US/help/terms_maps/)

若整合 Routes API，必須遵守另一套 Platform 與服務條款：其結果可以單獨以文字顯示，但不得搭配非 Google 地圖；位置座標可暫存 30 天的例外不等於 ETA 或矩陣也可保存。API 內容使用 Google Maps 歸屬標示，並與其他來源視覺區隔。[Routes 服務條款](https://cloud.google.com/maps-platform/terms/maps-service-terms#19.-routes-api)、[Routes 歸屬政策](https://developers.google.com/maps/documentation/routes/policies)

Platform 條款另有限制擷取、快取及使用 Google 內容改進機器學習模型的規定；本比較流程應與 JEV 模型測試資料管道分開。[Platform 條款第 3.2 節](https://cloud.google.com/maps-platform/terms)
