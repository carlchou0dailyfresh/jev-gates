# 配送展示的有限實測

以下是本機單次觀察，不是保留測試集或真實配送結果。案例、訊息、訂單及門檻均為合成/未校準設定，原始結果按實際執行保存；沒有事後改分數以得到想要的結果。

`pre-live-protocol.json` 在本機模型試跑前記錄案例及比較程式 SHA-256。其時間來自本機時鐘，並非第三方時間戳。`reference-scenario.json` 保存本輪教學案例。

`observed-localjev.json`：固定幾何估距矩陣上，以 LocalJev localjev-0.2 / gemma3:27b 執行 8 次請求、12 道問題（兩策略各4次）。此筆較早 schema 沒有內嵌referenceScenario，重播需本提交的原始scenario；新產生報告已內嵌參考案例。後續工程修補沒有改其推論或量測。

| 策略 | 建議刷新（含初始） | 模型請求 | 語意問題 | 同步求解時間 | 語意經過時間 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 每次重算 | 7 | 0 | 0 | 7.65 ms | 0 |
| 規則去重 | 6 | 0 | 0 | 2.13 ms | 0 |
| 單層 JEV | 4 | 4 | 4 | 12.41 ms | 19.61 s |
| 雙判斷 AND | 4 | 4 | 8 | 10.73 ms | 19.06 s |

兩個語意策略均未漏掉這組作者標記的事件；不能把小型案例的符合率當作模型準確率。相同事件的執行順序固定，沒有獨立暖機控制或延遲統計，不能從約0.55秒差異推論雙判斷更快。規則求解只有毫秒，本輪增加JEV後總耗時顯著較長。

比規則少2次建議刷新（6→4）是共享快照的政策決策比較，沒有逐策略重做地圖外呼，沒有實際付費節省證據。單層與雙判斷結果相同，而雙判斷題數更多；本輪未證明堆疊帶來額外效益。未填費率，金額保持null。

`observed-osrm-plan.json`：另外直接從OSRM取得台北道路矩陣與幾何，共2次HTTP、661個幾何點；求解720個站序，得18.4694公里、32.4033分鐘車程，加50分鐘服務共82.4033分鐘。這是一次道路估計，沒有實際行駛、即時車流或可停靠點確認。此道路觀察與上述固定矩陣模型實驗分開，不可混成同一筆實驗。

OSRM/OSM 來源與使用限制見 `docs/delivery-sources.md`。Google未設金鑰、未實際測試，TypeSafe同樣未測；不把LocalJev結果外推為官方JEV效益。

重播：

```sh
node workbench/server/delivery-research.mjs verify eval/delivery/observed-localjev.json
```

後續若要驗證商業效益，需用獨立標註事件、相同交通快照、真實費率、多輪隨機順序與實際配送資料，同時觀察漏處理率、逾時與總成本。
